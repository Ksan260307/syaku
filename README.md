# しゃくとりの森 — Inchworm Forest

小さな **しゃくとりむし** になって、虫の目から見た大きな世界（7 つのエリア）をのんびり探検する、アニメ調の 3D オープンワールドゲームです。
戦闘はありません。体を「Ω」の字に曲げては伸ばす、本物そっくりの歩き方で、名所と「しずく」を探し、
アリやカエル、クモやカマキリ、クワガタやトカゲ、モグラやコウモリ、スズメやハト、ライチョウやオコジョ、ヤモリやツバメ、ヤドカリやカモメなど **52 種のいきもの**（と、めったに会えない **レアないきもの 7 種**）に会いに行きます。
PC・ゲームパッド・**スマホ／iPad** で遊べます。

- **エンジン**: Unity 6 (6000.5.4f1) / URP / UI Toolkit / Input System
- **モデル**: Blender 5.2 の Python スクリプトですべてプロシージャル生成（`blender/scripts/build_forest_kit.py`, `build_creatures.py`, `build_park_kit.py`, `build_mountain_kit.py`）
- **音**: BGM・環境音・効果音も Python (numpy) で合成（`tools/make_audio.py`）
- **公開**: GitHub Actions → GitHub Pages（WebGL）

- **森**（しずく 45 個・名所 9 か所）・**川辺**（しずく 30 個・名所 6 か所）・**公園**（しずく 35 個・名所 10 か所）・**山**（しずく 40 個・名所 9 か所）・**山小屋**（しずく 30 個・名所 9 か所）・**海岸**（しずく 30 個・名所 9 か所）・**神社**（しずく 30 個・名所 9 か所）があります。
  森の東のはしにある **木の根のトンネル** を抜けると川辺へ、西のはしのトンネルを抜けると公園へ。川辺の滝の上の台地の奥（北東）のトンネルを抜けると山へ。山の山小屋の **とびら** に入ると、小屋の中へ。川辺の下流の東の岸のトンネルを抜けると海岸へ。公園の北東のさくの所のトンネルを抜けると神社へ。地図の下の「エリアの地図」のボタンで、一度行ったエリアの地図に切りかえられ、その地図の見つけた名所をタップすると、そのエリアのその名所へすぐ移動できます。
- いきものに近づくと **いきもの図鑑** に登録されます（57 種）。図鑑は「森・川辺・公園・山・山小屋・海岸・神社」のすみかで絞りこめます。まだ見ていないいきものは図鑑にヒントが出ます。
  見つけたいきものは、図鑑で **すみか**（どの名所のまわりにいるか・すんでいるエリアの地図の上の場所）が見られ、そばの見つけた名所へ **図鑑からすぐ移動** できます（ほかのエリアの名所へも）。
- 集めたしずく・名所・いきものの数で **きせかえ** が増えます（30 しゅ）。**いろ・ぼうし・めがね** を 1 つずつ、いっしょに身につけられます。
  - いろ（16）：わかば・きみどり・さくら・そらいろ・もみじ・よぞら・こがね・るりいろ・ふじいろ・ミント・ゆきんこ・すみいろ、
    もようつきの **いちごみるく**（水玉）・**はちみつしましま**（しま）・**レインボー**（尾から頭へ虹のしまが、ゆっくり流れる）、ぜんぶ集めると「にじいろ」。
  - ぼうし（10）：**ぴょこんげ**（頭のてっぺんから毛が 1 本ニュッ。歩くと、ぴょこぴょこゆれる）・キャップ・むぎわらぼうし・どんぐりぼうし・リボン・
    ニットぼう・花かんむり・ベレーぼう・シルクハット・おうかん
  - めがね（4）：まるめがね・サングラス・ハートのサングラス・ほしのめがね
  - ぼうしとめがねは、もう一度えらぶと外せます。どれも、曲がる体の頭の向きにぴったりついてきます。
- キノコの柄やかさ・切り株の壁・葉っぱの裏…しゃくとりむしは**どんな面でも這って登れます**。
  かたつむり・カブトムシ・クワガタ・トカゲ・カエル・カニ・カマキリの背中にも登って乗れます。地面の大きな落ち葉も、登って乗れる足場です。
- 軽く動くように：しゃくとりむしの体の変形は体の輪ごとに 1 回だけ計算し、草や小物はカメラが動いたときだけ数えなおし、
  画面の外のいきものは描かず、しゃくとりむしから遠いいきものほど動かす回数を間引きます。
  描くほうも、画面に入らない物・見えないほど遠い物は描かず、遠くの物は三角形の少ない形で描き、
  水の深さと色の写しは水が映るときだけ作ります
  （ブラウザでは 1 秒に 60 回まで描画。画質「かるい」では影を 1 段にして、いきものも近くだけ。「自動」では重いときに画面の細かさだけを下げます）。
  くわしくは下の「軽さのくふう」。
- がけを下りるときは 80 度までの斜面なら壁にそって回りこみ、それより急なら前へのり出して**落ちます**（小さな葉っぱの裏に勝手にはりつかないように）。
- 体長の半分くらいのすき間なら、体を伸ばしてまたいで渡ります。長く休むと「小枝のまね」をしてかたまります。
- 高い所では **糸を出してぶら下がり**、ゆっくり下りられます（長押しで糸をのぼって戻れます）。
  「ねらう」で 12 体長以内の好きな場所へ糸を飛ばすと、フックショットのように、糸がまっすぐ飛んで刺さり、体も一直線に引き寄せられます。
- 見つけた名所へは、地図の上の名所を**タップ（クリック）**するか「ここへ」で、すぐ移動（ファストトラベル）。
  着いた先やエリアの入り口では、その場所がいちばんきれいに見える所から、景色をゆっくり見わたしてから始まります。
  名所ごとに、その名所がよく見える所から始まります（切り株・大きな松・棚・はりなど、高い所の名所はその上から）。カメラが地面や物にぶつからない向きで、しずくの真上には着きません。
  動けなくなったらメニューの「動けなくなったら」で安全な場所へもどれます。
- 川辺では、**とびいし**・**倒れ枝の橋**・**葉っぱの渡し舟**（中州へ）を使って川を渡ります。
- 公園の遊具で遊べます。**ブランコ**は乗ると大きくゆれ、**シーソー**は乗った側へかたむき、
  **すべり台**はてっぺんから坂を下向きに進むと、出口まですべりおります。ジャングルジムや土管、砂場の砂山にも登れます。
- 松ぼっくり・どんぐりのかさ・落ち葉・小石などの小さな物は、どんぐりと同じように、押すと動いたり転がったりします。
  重さは本物と同じグラムで（1 単位 = 2.5cm の体積に、石や松ぼっくりの密度をかける）、地面にのせて置くので、勝手に転がりません。
  しゃくとりむし（約 0.1g）には重すぎる小石（0.3g より重い）は動かず、よじのぼって越えます。
  地面の大きな落ち葉も本物の重さがあり、強い突風のときだけ、地面とのまさつに勝ってすべります（しゃくとりむしが乗っている葉は、足でつかんでいるのですべりません）。
- しゃくとりむしが沈まない浅い水（深さ 0.1 まで）には入れます。公園の水たまりは、まん中まで歩いて入れます。
- 睡蓮の葉の切れこみの上でも、水に落ちずに渡れます。花だんのレンガのすき間には、入りこみません。
- 公園の大きなクヌギには、低い所から上まで太い枝がのびて、葉がしげっています。幹から枝へわたって、木の上を探検できます。
- BGM はエリアごとにちがいます（森・川辺・公園・山・山小屋・海岸・神社の 7 曲。移動すると、ゆっくり切りかわります）。
- 進行状況（20 秒ごと・大事な場面・タブを切りかえたとき）と設定はブラウザに自動保存されます。
- 遊んで気になった点を洗い出して直した **100 の改善** は [IMPROVEMENTS.md](IMPROVEMENTS.md)、
  しゃくとりむしといきものの **移動の改善 500**（2 回 × それぞれ 100 と、いきもののモーション 100）は [MOVEMENT_IMPROVEMENTS.md](MOVEMENT_IMPROVEMENTS.md)、
  重力・空気のてい抗・はね返り・糸・浮力・風・転がるどんぐり・大まかな当たり判定などの **物理計算の改善 200**（2 回 × 100）は [PHYSICS_IMPROVEMENTS.md](PHYSICS_IMPROVEMENTS.md)、
  森・川辺・公園それぞれの **エリアの改善 300**（空気と光・ただよう物・場所で聞こえる音・風景・遊びと道・地図・案内）は [AREA_IMPROVEMENTS.md](AREA_IMPROVEMENTS.md)、
  形や物の置き方の **違和感の直し 300**（宙にういた物・つきぬけた草花・重なった物・水の中で宙にういた飛び石・さくと幹など）は [AREA_FIXES.md](AREA_FIXES.md)、
  山の物の置き方の **遊びやすさの直し 100**（小道の付けかえ・道しるべ・登る道・とびいし・しずくと景色の前の草花・いきものの居場所）は [MOUNTAIN_FIXES.md](MOUNTAIN_FIXES.md) にまとめています。
  全エリアの **いきものの居場所の見なおし**（小道・景色・しずく・物の中・水べ・鳥の降りる場所・岸から見つけられるか）と、山の大きな松の根の直しは [CREATURE_FIXES.md](CREATURE_FIXES.md) にまとめています。
- **物と地面のなじみ**：しゃくとりむしは、体を Ω にまげられないほど低いすき間や、岩・タイヤの中へは入りこみません。
  上にかぶさる物（坂にのった岩の下など）の下では、頭の上げ方と体のこぶを低くし、坂で背伸びしても体のつけ根が地面にうまりません。
  坂で宙にういた岩や流木は坂にそってかたむけて地面にしずめ、動かせない岩（しずくがのっている滝のわきの大岩など）の下のすき間は、石でうめます。
  山の湧き水の泉と公園の水たまりは、下り坂の側に水面より少し高い土手があり、水のふちが地面からうきません。泉のまわりは、歩いて入れる浅い水ぎわです。
  山の大きな松の根は坂の地面にそって下り、オコジョのすみかは、坂にそった掘り出した土の山のまん中に、暗い穴があいています。
  公園のタイヤは面の向きをなおし（外から見えるペンキの色・しゃくとりむしが中へ入らない）、タイヤのしずくは、輪の内がわの上（穴の天井）にあります。
  泉の土手・タイヤの当たり判定のように、しずくの場所にかかわる形は、しずくを置いたあとに作りなおします（しずくの場所は変わりません）。
- クモの巣は、まん中から張った糸がとどく所（地面・幹・キノコの柄・岩）を支えにして、ゲームの中で張ります（宙にうきません）。
- 草花と苔は、エリアを作った最後に 1 つずつ見なおします（岩・さく・落ち葉をつきぬけて生えている物、同じ所に重なった物、小道のまん中の物を取りのぞき、ういた苔は地面にそわせる）。
- 見つけたいきものに、もう一度会うと：
  - **あいさつ**：しずかに近づくと、こちらを向いて、ぽよんと弾んで鳴いてくれる。
  - **なかよし**（★1〜5）：会うたびに上がる（同じ種は 25 秒に 1 回まで）。★1 で「すきなもの」、★3 で「ひみつ（本当のいきものの豆知識）」が図鑑にのり、★5 になると、会ったときに、とっておきのしぐさを見せてくれる。なかよしの鳥は、近くまで来させてくれる。
  - **しぐさの観察**：種ごとに 3 つのしぐさ（だんごむしがまるくなる、てんとうむしの死んだふり、モグラが顔を出す…）。見るたびに図鑑にスタンプがたまり、ぜんぶ見ると図鑑のカードが金のわくになる。
    観察になるのは、ちゃんと見ていたときだけ（画面のまん中のあたりに、ある大きさ以上で、物のかげにならずに映っていて、そのしぐさを少しのあいだ見ていたとき）。
    その場では、いきものの上に小さな光と音が出て、図鑑ボタンに新しいスタンプの数が出る（図鑑を開くと消える）。画面の上のおしらせは、つづけて見つけたときは 1 つにまとめて出し、設定の「しぐさの観察を知らせる」で消せる。
  - **大きさの記録**：一匹ずつ大きさがちがい（ときどき大物も）、会うたびにはかって、見た中でいちばん大きい・小さいを図鑑に記録する。
  - **あんない**：なかよし ★2 のチョウ・トンボ・ホタル・コウモリは、まだ取っていないしずくの方へ、光のあとを残しながら、あんないしてくれる。
  - きせかえ「るりいろ」（しぐさを 30 こ観察）と「ふじいろ」（5 しゅと、なかよし ★5）がふえた。
- 公園の花だんは、中の土をれんがのふちと同じ高さまで盛ってあるので、外から登って、土の上を歩いて、また外へ下りられます。
- スマホ・iPad では、「ねらう」を押したまま指をすべらせると、糸をねらいながら見まわせます（はなすと発射）。
- 川辺の葉っぱの舟は、しゃくとりむしに合わせて動きます。乗り場に近づくと待ち、頭もしっぽも乗ったら少しして出て、中州で待っているとむかえに来ます。乗ったまま着いたら、降りるまで待ちます。
- エリアごとに空気と光がちがいます（森は緑がかった霧とこもれび、川辺は水色のすずしい霧、公園は見通しのよい青空、山は樹冠のない、ひらけた空と白い雲）。
  森：切り株と大樹にサルノコシカケの階段、幹や根もとのすみのクモの巣、ふむと弾んで胞子が出るホコリタケ、丸太から洞への光るキノコの道しるべ、ときどき落ちてくるどんぐり。
  川辺：滝の虹、川を流れていく落ち葉と笹舟（滝を落ちて回る）、はねる魚、流木、滝のわきの岩の階段と滝の上のとびいし、下流の石の列。
  公園：シャボン玉、砂の城とバケツ、ビー玉、じょうろ、紙ひこうき、シロツメクサ、水飲み場のじゃぐちから水たまりへ落ちるしずく、ブランコのきしみ・シーソーのごとん・すべり台の音、砂と金属の足音。
- **山**（雲の見える山）：ふもとのトンネルから、北の山頂へ、ゆるやかに高くなる山。ところどころに岩の段（がけ）があります。
  平たい岩が段々にかさなる **岩の階段**、竹のかけいから水が落ちる **湧き水の泉**、コマクサやチングルマの **高山の花畑**、
  枝の先の葉のかたまりに乗れる **ねじれた大きな松**、とけ残った雪の **雪渓**、屋根まで登れる **山小屋**、下をくぐれる **岩のトンネル**、
  標柱と三角点とケルンのある **山頂**（まわりの山なみと雲海が見える）。分かれ道ごとに、行き先を指す道しるべ。
  山小屋の屋根へは山がわに立てかけたふみ板、岩のトンネルの上と大きな松へは倒れた木、岩の階段はわきの石段、泉の中の石へはとびいしで行ける。
  湧き水のこぽこぽ・高い所ほど強い尾根の風・遠くのウグイス・ナキウサギの「ピチッ」・ヒグラシの「カナカナ」が聞こえ、雪の上はさくさく、岩の上は石の足音。
- **山小屋**（あたたかい山小屋）：山の山小屋の中。人の大きさの丸太小屋なので、しゃくとりむしには、テーブルもベッドも岩山のよう。
  まきストーブとやかん・まきの山・テーブルとベンチ（マグカップ・パン・山の地図）・二段ベッド・かべの棚・編んだラグ・登山ぐつとリュック・
  かけ時計・ほした薬草・つるしたランプ・天井のはりの上のツバメの巣・かべのすそのネズミの穴。窓とあいたとびらの外には、高山の草原と山なみ。
  部屋の中は、かべと屋根のかげ（影の距離を部屋の奥までのばす）で、窓ととびらからさしこむ日ざしだけが明るく、光の筋の中をほこりがただよいます。
  ストーブの上には火の粉とやかんの湯気。まきのぱちぱち・かけ時計のこち・こち・ハエの羽音が場所で聞こえ、床板や家具の上は木の足音。
  かべ・はり・窓台・家具の上にも登れ、天井のはりの上からは、部屋じゅうが見わたせます。水はありません。
  パンくず・ひまわりのたね・マッチ・ボタンは、押すと動きます。山小屋のとびらは、山のしずく・いきものを置いたあとに作るので、山のしずくは変わりません。
- **海岸**（潮風の海辺）：北のトンネルから、砂丘をこえて、南の海へゆるやかに下る砂浜。波は沖から波打ちぎわへよせて、ぬれた砂の上を水がのぼったり下りたりします。
  口から中へ入れる **大きな巻き貝**、砂丘の上の白くさらされた **流木の丘**、ハマヒルガオとコウボウムギの **砂丘の花**、
  海につき出した **磯の岩場**（フジツボと海藻のついた岩・すんだ水の **潮だまり**）と、その先の **岬の大岩**（沖の小島の灯台が見える）、
  小川が海へそそぐ **干潟**（シオマネキの巣穴・歩いてわたれる浅瀬）。なくしたビーチサンダル・ガラスの浮き玉にも登れ、貝がらとシーグラスは押すと動きます。
  海は `ToonSea` シェーダー（浅い所はエメラルド、深い所はこい青。低い所から見ても白くならない）。遠くの波・海風・カモメの声と、波打ちぎわに近いほど大きな波の音。
  川辺から海岸へのトンネルは、川辺のしずく・いきものを置いたあとに作るので、川辺のしずくは変わりません。

## しくみ（実装メモ）

### しゃくとりむしの動き（`unity/Assets/Scripts/Player`）
シャクガの幼虫は胸脚（前の3対）と腹脚（後ろの2対）しかなく、中間の脚がありません。そのため

1. **引き寄せ**: 胸脚でつかまったまま、腹脚を胸のすぐ後ろまで引き寄せる → 体が Ω 字に持ち上がる
2. **伸び**: 腹脚でつかまったまま、前半身を持ち上げて前へ伸ばし、胸脚を次の場所へ下ろす

をくり返して進みます。ゲームでもこの2段階を交互に行い、体の中心線を
接線角 `θ(u) = a·sin(2πu)` の曲線（弾性体の座屈形に近い形）で作っています。
両端の距離 D と体長 L の比が第1種ベッセル関数 `J0(a)` になることを使い、表引きで `a` を解いています（`BodyCurve.cs`）。

Blender で作ったまっすぐなメッシュには、体のどの位置か・断面内の位置・法線を UV1〜UV3 に書き込んであり、
Unity 側で毎フレームこの曲線に沿って曲げています（`InchwormBody.cs`）。
次に手（脚）を置く場所は、表面に沿って少しずつ進むレイキャストで探すので、床→壁（凹んだ角）や崖のふち（出っ張った角）、裏側まで這って回り込めます（`SurfaceProbe.cs`）。

### 絵づくり（`unity/Assets/Shaders`）
- `ToonLit`: 2階調 + 柔らかい境界のトゥーン、青紫がかった影色、リムライト、アニメ風ハイライト、裏面法の輪郭線
- `ToonFoliage`: 草花用。風でそよぎ、しゃくとりむしが通ると草がかき分けられる。逆光で葉が透ける
- `ToonWater` / `ToonRiver`（川と、鏡の水たまり：深さで色が変わり、空が映り、波が光る）/ `ForestSky`（樹冠のすき間から見える空）/ `LightShaft`（木漏れ日の光の筋）/ `Dewdrop`
- 太陽光に木漏れ日のライトクッキー、ブルーム・色調整のポストエフェクト

### 森・川辺・公園・山（`unity/Assets/Scripts/World`）
地形・小物の配置はシード値から決定的に生成します（`WorldGenerator*.cs`, `ForestLayout.cs`, `RiverLayout.cs`, `ParkLayout.cs`, `MountainLayout.cs`）。
エリアは `Areas.cs` の `AreaLayout`（地形の高さ・水面・名所・トンネル）で抽象化してあり、移動するたびにそのエリアを生成し直します。
1 単位 = しゃくとりむしの体長（実寸で約 2.5cm）なので、どんぐりは岩、キノコは塔、切り株は山のような大きさです。
大量の草花・小物は GPU インスタンシング＋セル単位のカリングで描画しています（`InstancedRenderer.cs`）。

川辺は滝で段差のある小川（`ToonRiver` / `Waterfall` シェーダー）。葉っぱの渡し舟は `MovingPlatform` で、
しゃくとりむしの手足の位置を「舟から見た位置」で覚えておくので、乗ったまま一緒に運ばれます（`SurfacePoint.Updated`）。
公園のブランコの座板・シーソーの板・すべり台の見えない「そり」も同じ動く足場です（`ParkRides.cs`）。
川辺から山へのトンネルは、あとから足したもの（`GateDef.late`）で、川辺のしずく・いきものを置いたあとに作るので、川辺のしずくの場所と数（セーブの ID）は変わりません。
山小屋（`HutLayout.cs` / `WorldGenerator.Hut.cs`）は、平らな床の地形の上に、部屋（丸太のかべ・屋根うら・はり）と家具を置いたエリアです。
山と山小屋をつなぐのはトンネルではなく **とびら**（`GateDef.door`）で、とびらの面の前に頭が入ったら移動します。
屋根うらの当たり判定は、部屋の内がわだけを向いた片面の板なので、カメラは屋根の外へ出ず、上からのレイ（しずく・鳥の下りる場所）は通りぬけます。
神社（`ShrineLayout.cs` / `WorldGenerator.Shrine.cs`）は、高い基壇と石段の坂を地形で作り、その上に鳥居・お社・灯籠などを置いたエリアです。
公園から神社へのトンネルも `GateDef.late` で、公園のしずく・いきものを置いたあとに作り、トンネルのうしろのさく（`Park_Fence`）だけを、しずくを置いたあとではずします（`RemoveSolidsNear`）。
お社の鈴は `ShrineBell`（鈴緒の線にしゃくとりむしの頭が近づくと鳴る）。フクロウの頭は別のメッシュで、首（`CreatureRig.FukurouNeck`）のまわりにまわして、しゃくとりむしを見ます。

### いきもの・図鑑・きせかえ（`unity/Assets/Scripts/Gameplay`）
- `SpeciesCatalog.cs`: 52 種＋レア 7 種の定義（動き方・大きさ・羽・脚・歩き方・発見の距離・図鑑の文）。
  山のいきものは、似たくらしのなかまの動き方をまねる（`behavesLike`：ライチョウはハト、リスはトカゲ、オコジョはモグラ…）うえに、種ごとの鳴き声やしぐさを足してある
- `Creatures.cs`: 群れごとの動き（うろうろ・行列・ひらひら・ぴょん・鳥の飛び立ち・水面すべり・ホバリング・待ちぶせ）と、体・脚・羽・光をまとめてインスタンス描画。
  大きないきものには当たり判定（レイヤー `Creature`）があり、しゃくとりむしが乗れる
- `CreatureRig.cs` / `CreatureRig.g.cs`: 脚の付け根の位置と、ひざで曲がる手足の関節の位置（Blender のスクリプトが書き出す）、
  手足の IK（`SolveLimb`）と歩く足の行き先（`StepTarget`）、Blender→Unity の座標変換。
  Blender では `legs()`（細い脚）・`leg_part()`（形を自由にかく脚）・`limb()`（ひざで曲がる手足）でかいた手足を、`split_legs()` が右側だけ別のメッシュにする
- 図鑑の絵は Blender でモデルを並べて描き出した PNG（`unity/Assets/UI/Creatures`）
- `Skins.cs`: きせかえのいろはシェーダーの色相・彩度・明度シフト（`_HUE_SHIFT`）を MaterialPropertyBlock で切り替え。
  もようは、体のどこか（尾 0 → 頭 1）と体のまわりの角度（どちらもしゃくとりむしの UV）で、しま（`_Stripes`）・水玉（`_Dots`）・体にそった色相（`_HueAlong`）をかく
- `WormWear.cs`: ぼうし・めがね（`blender/scripts/build_wear_kit.py` で、頭のまん中を原点に作ったメッシュ）を、毎フレーム頭のまん中と向き
  （`InchwormBody.HeadCenter` / `HeadForward` / `HeadUp`）に合わせて置く。ぴょこんげは、頭の加速でばねのようにゆれる。
  きせかえの画面の絵（いろは Ω の字の全身、ぼうし・めがねは頭のアップ）も、同じスクリプトが Blender で描き出す（`unity/Assets/UI/Wear`）

### 軽さのくふう
ゲームの中身（いきものの動き方・当たり判定・ルール）は変えずに、毎フレームの計算をへらしています。

- **いきものを動かす回数**（`Creatures.UpdateInterval`）：しゃくとりむしから 10 m 以内のいきものは毎フレーム動かします。
  それより遠いものは、いま動いているか（歩く・跳ぶ・落ちる・転がる・すべる）とじっとしているかで、2〜6 フレームに 1 回にします。
  とばしたフレームの時間はためておき、次に動かすときにまとめて進めるので、どのいきものも時間はおくれません。
  回数はカメラの向きでは決めないので、どこを見ていても、いきものの動きは同じです（描くかどうかだけはカメラで決めます）
- **近くのいきものさがし**（`Creatures.Gather`）：4 m 四方のますに分けた格子をフレームのはじめに作り、近くのますだけを見ます。
  配列は使いまわすので、毎フレームのメモリ確保はありません。物音におどろく（となりの仲間もつられる）・押しあい・
  転がるだんごむしを押す・天敵をさがす・ホタルの光のリズムに使います
- **計算の順番によらない結果**：ほかのいきものの位置・速さは、フレームのはじめに写しておいた値を読みます。
  アメンボどうし・まるくなっただんごむしどうしのぶつかり合いは、ステップのはじめに 1 組ずつまとめて解き、
  2 匹とも、はじめの速さから同じだけ反対向きにはね返ります（`Creatures.ResolveContacts`・`ShakuPhysics.ContactKick`）。
  運動量が保たれ、計算する順番や、どちらが先に動くか（間引き）によらず同じ結果になります
- **考えごとの上限**：行き先さがし（ちょうの休む花・バッタやカエルの跳ぶ先・ハエトリグモの跳ぶ先・トンボやホタルのとまる所）は
  1 フレームに 6 回まで。こえた分は次のフレームにまわします（逃げるときは待ちません）。いっせいに考えて、1 フレームだけ重くなるのをふせぎます
- **一度はかれば足りるもの**：アリの行列の道の区間の長さは、作ったときに一度だけはかって使いまわします
- **読み込み中に、ひととおり描いておく**（`RenderWarmup`）：WebGL ではシェーダーや形のデータを、はじめて描くときに用意するので、
  新しい物や大きないきものがはじめて画面に入った瞬間に、一瞬止まります（山では 0.3〜1.3 秒）。
  エリアの読み込み画面のあいだに、草花・小物・いきもの・地形・水をひとつずつ、カメラの前にとても小さく描き、遠くで使う三角形の少ない形も先に作ります。
  まとめ描き（インスタンシング）のシェーダーは、まとめる数（32 きざみ）ごとに別に用意されるので、材質ごとに、どの数でも 1 回ずつ描きます。
  水が見えるときだけ使う描き方（深さを先に描く）と、影を落とす物が画面にないときの描き方も、このあいだに一度通します。
  ブラウザでの計測（山に着いて見まわし・歩く、1280×720）：止まる時間 0.34 / 0.61 / 1.3 秒 → いちばん長いフレームが 0.13 秒（着いた直後の 1 フレームだけ 0.24 秒）
- **大きないきものは 1 ぴきずつ描く**：体の大きないきもの（リス・ナキウサギ・ライチョウ・カラスなど）は、同じ形をまとめずに 1 ぴきずつ描きます。
  手前から順に描かれるので、大きな体のうしろの地面の色を、むだに計算しません
- **画面の細かさ**（`GameManager.StepRenderScale`）：画質が「自動」のとき、45 fps を下まわると描画の解像度を 0.1 ずつ下げ（0.7 まで）、
  55 fps 以上にもどると、もとの細かさまで上げます。見た目だけで、ゲームの計算には影響しません

エディタでの計測（森の 4 か所を歩く・1 フレームあたり）：いきものの計算 0.83 → 0.67 ms、0.77 → 0.63 ms、0.74 → 0.63 ms、0.54 → 0.46 ms（川辺）。
スクリプトの毎フレームのメモリ確保は 0 バイトです。

#### 描く量のくふう（GPU）
見た目は変えずに、GPU が 1 フレームで描く量をへらしています。どれも「画面にどう映るか」だけで決める調整で、
ゲームの計算（動き・当たり判定）には関係しません。

- **水が映るときだけ、深さと色の写しを作る**（`WaterView`）：池と川のシェーダーは、カメラの深さと色の写しで
  水の深さの色・岸ぎわの泡・水中のゆがみを描きます。ほかには使わないので、水面が視野に入らないフレームは写しを作りません。
  WebGL で MSAA を使うと、深さの写しのために「深さだけを先に全部描く」処理が入るので、これがまるごとなくなります
- **見える物を 1 つずつ数えなおす**（`InstancedRenderer`）：16 m のますで大まかに選んだあと、1 つずつ
  - 画面に入らない物は描かない（影を落とす物は、影の絵にだけ描く）
  - シェーダーで完全に消える遠くの草（52 m より先）は描かない
  - 影の届く距離より遠い物は、影の絵に描かない
  - 近い物から順に描く（手前の物で隠れた奥の色を、GPU が計算しなくてすむ）
- **遠くの物は、三角形の少ない形で描く**（`DetailMeshes`）：草花・岩・キノコ・葉・木・いきものは、取り込みのときに
  三角形を段階ごとに半分ほどにした形も作っておき（Unity の Mesh LOD）、画面での大きさで選びます
  （物の直径がおよそ 130 ピクセルより小さく見えると 1 段。形のずれは 1 ピクセルに満たない）。
  頂点・色・UV はもとのままです。**当たり判定は、いつもいちばん細かい形**（`DetailMeshes.ForCollision`）なので、
  登る・すべる・ぶつかるは前とまったく同じです
- **いきものの影と描く範囲**：影の届く距離より遠いいきものは影の絵に描かず、描く範囲を実際にいる場所だけにします
  （前は 400 m の箱だったので、影の絵の近くと遠くの両方に、全部のいきものを描いていました）

ヘッドレスの Chrome（Intel UHD Graphics・1280×720）で、WebGL 版の GPU 時間を 1 フレームあたりではかりました。

| 画質 | タイトル | 探検（止まる） | 探検（歩く） |
| --- | --- | --- | --- |
| きれい | 51 → 30 ms | 54 → 32 ms | 58 → 34 ms |
| かるい | 26 → 18 ms | 31 → 20 ms | 31 → 23〜32 ms |

歩く場面は、行き先にたくさんの物が見えるうえ、近くにどのいきものがいるかで毎回かわるので、ばらつきが大きくなります
（「かるい」で歩くと、もともと画面の中の物が多い場所なので、へり方は小さめです）。

### スマホ・タブレット
- タッチされたら画面のボタンとフローティングスティックを表示（`GameUI.cs`）。スマホでは UI の基準解像度を下げて大きく表示
- 縦長・横長の画面に合わせてレイアウトを切り替え（USS の `.portrait` / `.short` / `.compact`）
- WebGL テンプレートで、ピンチやダブルタップによるページ拡大を止め、高解像度端末では描画解像度を抑える

### 止まらないためのくふう（WebGL）
WebGL では、エディタでは気づかないことでページごと止まってしまうことがあるので、まとめてふせいでいます。
- 例外のあつかいは「スタックトレースなしで、すべて」（`FullWithoutStacktrace`）。null の参照や配列の外を読んでも、そのフレームの処理だけが止まり、
  ゲームは続く（山で比べても 31 fps のまま。wasm は 1% ふえるだけ）
- 小数を整数にするとき（いきもの・小物・草花のます目の番号、つぶの数、時間の表示）は、NaN や大きすぎる値を 0 にする
  （`ShakuMath.FloorToIntSafe` / `RoundToIntSafe` / `CellIndex`。WebGL では、そのまま int にすると止まる）
- しゃくとりむしの体・糸・落ちる位置のどこかが こわれた数になったら、すぐ最後の安全な場所へもどす。いきものも、前の場所へもどして止める
- セーブと設定の こわれた値（NaN・範囲の外）は、読みこむときに ふつうの値へもどす。すみかの記録の こわれた行は使わない
- 糸でいろいろ動きまわる総合テスト（ねらって発射・カメラでねらう・たぐる・切る・こぐ・のぼる・下りる・つかまる・ふちから下りる）で、
  エラーも こわれた数も出ないことをたしかめている

## 公開（CI/CD）

`main` に push すると `.github/workflows/deploy-pages.yml` が動き、GitHub Pages に公開されます。

1. GitHub のリポジトリ設定 **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする（初回のみ）
2. そのままでも、リポジトリに入っているビルド済みの `docs/` が公開されます
3. GitHub Actions 上で Unity からビルドしたい場合は、**Settings → Secrets and variables → Actions** に次を登録します
   - `UNITY_LICENSE` … Unity Hub でライセンスを有効化したときにできる `Unity_lic.ulf` の中身
     （Windows: `C:\ProgramData\Unity\Unity_lic.ulf`）
   - `UNITY_EMAIL` / `UNITY_PASSWORD` … Unity アカウント
   - （Pro ライセンスの場合は `UNITY_SERIAL`）

   登録すると、push のたびに [game-ci/unity-builder](https://game.ci/) で WebGL をビルドして公開します。
4. ワークフローの権限は、ふだんは読むだけ（`contents: read`）。公開のジョブだけが `pages: write` / `id-token: write`、
   Unity のテストのジョブだけが `checks: write` を持ちます
